# Minimal property challenger: consumer cuts before a new service

**A whole guest property service is not established as necessary.** The smaller next design is to keep genuine Samsung values, remove/adapt identified optional guest actions, and admit only exact remaining keys whose real consumers and host effects have been reviewed. No unavoidable required security-key conflict is proved by the present evidence. This also does **not** prove ColorOS boots without added properties or that an empty key set is the final minimum.

The [earlier property-view plan](retained-property-view-plan.md) remains frozen. Its private-area/client/service requirement describes that proposed branch; it is not proof that every route to the full goal requires a new daemon. This challenger preserves the full PIN/fingerprint/app-key/CE/return requirements and does not relax Samsung policy or count optional removals as completed integration.

## One concrete smaller cut: optional OPPO boot-clock action

H independently closed actual staged `oplus-services_patched.jar` `a854468f…`:

- `OplusNewNetworkTimeUpdateServiceFeature.checkSystemTime()V` reads `persist.sys.device_first_boot` with default **true** at PCs15–16. It can also enter the reset path when current time is below50,000,000ms at48–53, even with that flag false. It invokes `SystemClock.setCurrentTimeMillis`178 and ignores its Boolean result. The calendar's month depends on an additional feature; the script comment's January1 is not universal. No real clock change was performed or native permission result proved.
- `Lcom/android/server/NetworkTimeUpdateServiceExtImpl;->checkSystemTime()V` is exactly four instructions: feature getter0, result3, interface call4, return7. Body SHA256 `fee9acf2def335b4f44020e5228547dd5145f6a6b7b591bdecf1eb4355ab163b`.

The next source-approved optional-feature derivative can omit this **void OPPO action before its lazy getter**. That avoids realizing its feature solely to suppress the later setter, returns no authentication/success value, and leaves real Samsung time ownership intact. It is a precise proposal for one method, not emitted code, full caller/world closure or proof every guest clock writer is gone. Removing the associated global first-boot override is justified only after the actual consumer cut/source composition is admitted. A private property area alone would not close the second clock branch or its non-property `SystemClock.setCurrentTimeMillis` request. The actual downstream endpoint, native permission and execution are not proved by these two bodies.

## Smallest source/control contract to investigate next

1. **Retain host values; do not apply the bulk candidate manifest globally.** Keep the original filters as a floor, not as host-nonuse proof. First prepare the exact source-selected key requirements and optional consumer dispositions offline. No runtime setter/launcher is emitted here.
2. **Prepare the exact OPPO clock-wrapper omission above**, then close the actual guest rescue module/registration and required privilege/package policy before removing their existing protection gates. This is a smaller discriminating source cut than starting a second property service.
3. For any remaining additive key, bind the exact value to a required reached guest consumer and its lifetime. Demonstrate that adding it does not change any reached genuine host reader's default/policy, or adapt the guest consumer to its real supplied configuration/API. **Undefined on host, OPPO prefix, or a few absent literal references do not prove that.** Reject existing-key overrides; do not alter physical/security truth to imitate an OEM identity.
4. Separate deliberately shared hardware/init controls from guest data. Existing `ctl.start/stop/restart` includes host zygote, display/audio, netd and GNSS operations; these are not generic permitted forwarding. `sys.usb.config` and global power commands likewise require the real selected Samsung/control owner. Keeping a property does not authorize the command or prove coexistence.
5. **No broad restore or `--added-only` shortcut.** The old source's `--added-only` skips only the value-restoration loop978–979; its deletion loop970–975 can still delete legitimate host additions. A key ledger also cannot by itself distinguish later writers or retract already observed policy changes. Prefer eliminating shared guest writes; any retained shared addition needs genuine writer/drain and cleanup ownership before runtime approval.

For this conflict-driven challenger, a required consumer needing a different simultaneous value from the same host/native reader would justify reconsidering private property infrastructure or rejecting that topology. That decisive key/consumer pair is **not yet proved**; this criterion does not rule out other source-demonstrated infrastructure needs. The present result chooses minimal consumer/admission cuts as the next investigation priority, without claiming the minimum complete set is closed or reducing the full goal.
