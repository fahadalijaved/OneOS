# Prepared private retained PIN transport

The prepared endpoint/client passed the separate actual SDK37/D8 build and
authored JDK model workflow (42 scenarios, 312 checks), with independent saved-byte
review. They remain unselected and default closed. No production module opens or
publishes the endpoint, and neither class establishes a guest issuer, physical
subject reservation or native authority lease.
This component does not edit the existing Binding, operation Owner or direct-55
client. Historical Owner compilation9095 used Binding9ecdc; that evidence resolves to
its preserved source snapshot. Root's current Bindingf7f006 adds the independently

Root selected a narrower lifetime contract than the earlier API proposal. The
proposal's sticky unresolved-reply HOLD and automatic shared-Owner close are
**superseded**: endpoint close never opens/closes the shared Owner, and no permanent
HOLD is inferred merely because the canonical Binder wrapper may serialize an
escaping exception later. `localRpcStacksIdle()` describes admitted Java
`onTransact` frames through local decoding, original call, reply construction,
decoded-PIN cleanup and boundary error handling. Its final decrement precedes
the framework/native completion outside this method. It grants no transport,
queue, remote-delivery, native-work or original-resource disposal acknowledgment.

`PreparedRetainedPinEndpoint.prepare(actualOwner)` requires canonical main Looper
thread, same authored defining loader as the operation Owner, and canonical host
framework widget/Parcel/Binder Classes. It retains the actual Owner and cached
original host credential CREATOR. These checks constrain placement; they do not
attest source/process ownership. Package-private `openIngressForControl()` is
only a future genuine bootstrap lifecycle seam. The controller must separately
order shared-Owner opening and closing, genuine guest handle delivery, physical
subject/currentness and continuous original/native custody. No public Boolean,
callback, PID, descriptor or supplied Binder grants these. No original reference
is released based on the count; integration retains the endpoint/Owner for the
process lifetime.

The new private protocol is descriptor
`com.appleexploit.oneos.security.IRetainedPinEndpoint.v1`, code1, synchronous
flags32. Request: canonical interface token, version1, original typed PIN object,
no trailing data. No user ID, serial, caller claims or operation flags are on the
wire. Host captures real Binder calling UID and requires1000 before decoding an
admitted frame. Unknown codes keep original Binder behavior and are uncounted;
the descriptor exchange provides no admission. Closed requests never decode.
An admitted frame may continue decoding, invoking and replying after close.

The cached genuine host CREATOR returns an owned decoded credential. Its exact
canonical class and original `isPin()` are checked, then the actual Owner runs
once on this same worker/caller with its internally bound subject and flags0.
There is no identity clear, executor, main hop, retry or direct private LSS path.
Normal reply uses original `writeNoException()` and typed original response
writer with `PARCELABLE_WRITE_RETURN_VALUE`; genuine null remains null.
Original codec comparison a83398d8 covers the credential type/array/two booleans
and response code/Duration seconds+nanos/HAT/handle. No adapter field recoding,
Duration default, HAT omission or fabricated success is introduced.

Every successfully returned decoded credential is closed in finally, including
trailing-field, wrong-PIN, verification and response-writer failures. Actual host
close calls zeroize, whose null guard permits the original verification's prior
zeroization. Cleanup failure preserves an existing primary, including identical
Throwable or failed suppression. A CREATOR that allocates and then throws before
returning an object leaves an inaccessible temporary outside this ownership
claim; no physical heap/native erasure claim is made. Host data/reply Parcels are
borrowed framework objects and are never recycled or retained by this code.

Local original `RemoteException`, `RuntimeException` and `Error` instances escape
unchanged after cleanup. An unsupported checked Throwable becomes a fixed-message
`RemoteException` with its local cause. This new boundary translation is explicit;
Throwable identity across processes is not claimed. Canonical Binder owns later
exception serialization/native reply handling. Neither a Java true return nor
idle count proves delivery or absence of original effects. Failure after entry
is not retried and does not imply rollback.

The client retains only the supplied private Binder and genuine guest response
CREATOR. It requires actual process UID1000 and actual Binder calling UID1000,
canonical guest framework placement and a canonical existing PIN. UID1000 is a
restricted operation profile, not guest process/source authentication. It sends
exactly one transaction, marks its owned request sensitive, uses original guest
credential writer and original response CREATOR after genuine `readException()`,
then refuses trailing response data. False transact, death, errors and malformed
responses are failures; a decoded original null is unavailable, not success.

Only the client's two acquired Parcels are recycled, each once, with the first
acquisition covered if the second fails. Both cleanup attempts occur, preserving
the exact primary and safely suppressing distinct cleanup failures. The guest
PIN is borrowed: never stored, logged, copied or closed. Client close is terminal
local admission cutoff; already admitted calls may serialize/transact/return
later. It revokes no host handle and makes no remote-idle claim.
