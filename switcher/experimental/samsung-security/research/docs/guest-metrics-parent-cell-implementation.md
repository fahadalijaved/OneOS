## Implemented ownership and outcomes

The private controller installs one class/loader claim before reflection and holds the exact owner/born pair. Retire before capture writes a terminal owner tombstone. Duplicate capture is refused; the claim is never cleared. Wrong-owner status/phase/retire refuses without taking over the known owner. Preparation faults produce a retained failed cell, not a new backend or default metric.

Producer.prepare and Endpoint.prepare run outside OWNER_LOCK. Any returned Producer/Endpoint is adopted before the preparation credit is released. A late Endpoint after retirement is retired under an exact identity acknowledgement. Phase100 during preparation terminally closes the attempt with REFUSED_ORDER; no delayed activation is queued. A valid first phase100 owns an activation credit, calls the actual Endpoint.activate outside the lock, and commits ACTIVE only if retirement has not won. ACTIVATION_APPLIED records that guarded transition; retirement can win immediately afterward, so it is not current readiness.

Private dispatch admits/counts only the exact pair in ACTIVE, then invokes the owned Endpoint's local Binder.transact1 with unchanged borrowed packets/flags. The lock is not held across protocolBinder/transact. Actual dispatch Boolean and supported/checked Endpoint failure behavior propagate; cleanup cannot replace the primary failure. Public dispatch remains OFF in this build. Canonical local Binder's already reviewed position reset behavior is not changed.

Retirement closes admission, claims at most one action for the exact Endpoint, invokes Endpoint.retire outside the lock and records acknowledgement only after normal return. An action failure latches UNCERTAIN and retains owners without retry. Preparation, activation and dispatch keep their own-use credits through cleanup; the separate retirement action credit prevents false completion while that call runs. COMPLETE requires terminal admission, no use/action credits, the actual Endpoint retirement acknowledgement (or no possible late Endpoint), and no uncertainty. Pure polls perform no cleanup or retry.

This is only the cell's Java-use completion. Previously reply-admitted results may arrive later. Original DMS, native Binder delivery, other callbacks/consumers and global/native/return drain remain unassembled. There is no endpoint getter or alias/publication API.
