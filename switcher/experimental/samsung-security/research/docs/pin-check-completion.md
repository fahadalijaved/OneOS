# Same-request PIN progress completion cell

`PinCheckCompletion` is a package-private per-request scheduling cell. It joins an actual source progress event with the SAME request's original canonical final response and returns the existing original progress-delivery Runnable at most once. It never creates a Runnable, invokes it, posts a Handler message, reports DPM, dismisses keyguard, issues a source/user lease, retries a request or drains native/callback work. Package-private API:

* Constructor `(Object actualRequest,Object actualProgressReceiver)` retains nonnull actual reference identities. No names, equals(), UID or scalar request-ID grant is accepted.
* `recordProgress(request,receiver,Runnable originalDeliveryTicket)` records the original event and its already-created exact Runnable. It returns that same Runnable only if a final canonical MATCH is already recorded and the cell remains active/unconflicted; duplicate events never release another ticket.
* `recordFinal(request,receiver,VerifyCredentialResponse originalResponse)` adopts the exact first result before off-lock calls to the three original predicates. A prior original event plus MATCH returns its exact retained Runnable once; final-only MATCH returns null. A later genuine event after MATCH may return once. Null, nonmatch, actual predicate failure, conflicting final and unavailable/uncertain dispositions never release progress success.
* `recordFailure(request,receiver,Throwable actualFailure)` records unavailable failure without retaining/logging its text or rethrowing/substituting the caller's actual failure. The producer still owns original propagation/reporting. `recordTransportUncertain(request,receiver)` preserves a distinct actual transport-uncertain disposition, never an invented retry/error result.
* `cancel(request,receiver)`, `markStale(request,receiver)` and `close()` retire scheduling irreversibly; no reset/rebind/rearm. Identity mismatch is ignored and cannot poison the current request or trigger getter access.
* `finalKind()` is result/availability data, not a ready Boolean. `responseFor(request,receiver)` returns the SAME borrowed first object for correct identities, including after logical retirement. A conflicting result has an explicit CONFLICT view; the first object is not replaced. No secret/status serialization or diagnostics are emitted.

Every claim is linearized under the private lock. No original getter/callback runs under that lock. Cancellation/staleness/close while a predicate is reading prevents the final claim; getter failure is recorded as unavailable and its exact Throwable propagates. Different contradictory finals/failure-after-final poison future claims, while duplicate reference-equal final/event delivery does not return another ticket. The private flag is scheduling progress, not source authenticity. Unknown nonmatch/error categories stay genuine result data and never reach DPM here.

A ticket already returned before cancellation cannot be recalled by this cell; returning a Runnable is not enqueuing/executing it or acknowledging drain.
