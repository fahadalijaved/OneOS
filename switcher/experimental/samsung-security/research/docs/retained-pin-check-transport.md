# Prepared private PIN check transport

This is the source-contract card for the reviewed code2 route; Root's fresh-cohort
SDK/D8 result is a separate evidence stream. It is default closed, unpublished and
unselected. This report
does not inherit the old code1 artifact/model acceptance for the changed sources.
No Cell, ordinary keypad callsite, current-subject issuer or UI completion gate is
integrated here, and the capture-only host module does not open these owners.

The endpoint adds `prepareWithCheck(verifyOwner, checkOwner)` and final optional
CheckOwner/factory references. The original `prepare(verifyOwner)` remains a
verify-only endpoint; it does not resolve callback metadata. Preparation calls
`checkOwner.checkForEndpointControl(verifyOwner)` before and after metadata work,
using the actual same-base/control-thread check rather than supplied IDs or a
ready Boolean. All authored owners must share the actual defining loader.

Check preparation resolves canonical host
`com.android.internal.widget.ICheckCredentialProgressCallback` and its original
Stub using initialization-disabled class lookup. It verifies their canonical
framework placement, interface/Binder ancestry, and the Stub's declared public
static9 `asInterface(IBinder)` Method with the exact canonical return interface.
The Method is cached once; no `setAccessible`, callback forwarding Stub, backend
construction, lookup or per-call metadata search is added. Invocation of that
original factory on the worker can perform its genuine local-interface/Proxy
work; initialization-disabled lookup is not a universal no-clinit guarantee.

Private code2 uses the existing descriptor/v1 and synchronous sensitive flags32.
After its own endpoint OPEN/configured admission and actual incoming UID1000
check, it decodes original typed PIN plus strong callback Binder and rejects
trailing data. There is no wire user, serial or verification flags. Closed or
unconfigured endpoint check routes refuse before decoding. A separately closed
CheckOwner still refuses at its own operation entry; the future controller must
order owner and endpoint lifecycle independently. Endpoint opening/closing never
opens or closes either shared owner.

The cached original factory consumes the **same received callback Binder** once.
Null is passed through the genuine null factory path. The resulting canonical
IInterface is passed to `checkOwner.checkPin` on this same worker/caller; the
actual CheckOwner selects the bound physical subject and original public LSS
check operation. There is no verify substitution, direct private doVerify entry,
identity clear, executor hop, callback synthesis or retry in this transport.

Normal replies preserve the original nullable response and its original writer.
Every returned decoded PIN is closed in finally, including callback decode,
factory, original operation and writer failures. Primary Throwable identity
wins cleanup/self-suppression failures. Original local RemoteException/Runtime/
Error escape; other checked failures become a fixed RemoteException with cause.
Reflection target causes are unwrapped once. Cross-process Throwable identity,
partial-constructor temporary erasure and physical/native erasure are not claimed.
Platform data/reply Parcels are borrowed and never recycled or stored.

Both routes share the endpoint's Java-stack count only. It spans their local
decode, original call, reply construction and local cleanup/error handling;
later native delivery, callback queues and framework exception handling are
outside it. Final references retain owners while this endpoint is live; the real
controller must retain the endpoint/owners for the selected process lifetime.
Neither zero count nor close grants native/global drain, disposal or source
handoff. Admitted frames may continue after endpoint close.

The client adds `prepareForCheck(privateBinder)` with cached canonical guest
callback interface Class. `checkPin(PIN,IInterface nullable)` requires actual
process/calling UID1000 and an actual instance of that canonical interface when
non-null. It calls the original object's `asBinder()` once; a non-null interface
must yield a non-null Binder. It writes that exact Binder with `writeStrongBinder`,
not an adapter-created callback. It performs one code2 transaction and uses
original readException/response CREATOR, preserving null and rejecting trailing
reply data. Both owned Parcels are attempted once through all partial acquisition
and serialization/read/transport errors, preserving the primary. The caller's
PIN and callback are borrowed and never closed, logged or retained by the client.

The source inverse proof restores exact endpoint aafc1441/client fef96e5a and
Parcel aaec012f beforeimages. Legacy endpoint preparation and all code1 work
remain identical except the one new early dispatcher line; legacy client prepare
and verify method bodies are byte-identical. Constructor overload scaffolding
only supplies optional check metadata. The Parcel compiler-only projection adds
only `readStrongBinder():IBinder` and `writeStrongBinder(IBinder):void`; both are
public-final17 in the pinned host8095/staged5cb declarations. All compiler ABI
definitions remain excluded from program DEX and model/runtime classpaths.

Mandatory source evidence is the original callback factory/wire proof f3dd8571
and ordinary keypad semantics review7e584cf9. ABI compatibility and UID/Binder/
descriptor possession authenticate no source or physical subject. Genuine guest
handle issuance, current-task/user/serial admission and continuous original/native
custody remain external. The real keypad also needs the same-request genuine
progress plus final-result/remaining-policy completion gate and uncertainty-aware
failure/accounting path identified by that review. This transport does not wire
or manufacture those gates. One-way callback return is not its execution/drain
acknowledgment. Existing Samsung authority work remains live; presentation switch
alone is not a reason to demand a global LSS drain.

Exact beforeimages, whole-source inverse, ABI checks and source-review pins are
in the inventory/private source packet. Only authored static text/hash and saved
declaration checks ran here; no compiler, model, OEM/Android/native, device or
network operation was performed by this source preparation.
