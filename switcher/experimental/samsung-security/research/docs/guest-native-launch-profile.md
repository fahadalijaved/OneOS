# Samsung installd launch-input contract

**Static source contract only; no launcher, daemon or phone execution.** A private sibling must own a real process profile and Samsung code/root/loader inputs before exec, covering the interpreter, library constructors and original `main`. The existing filesystem owner and publisher-only `511dac…` alias supply neither that profile nor native startup readiness. This is a finite next seam, not a claim that a second correctly owned process is impossible.

The audit reuses the frozen [native-owner](retained-installd-native-owner.md), [routing](retained-installd-routing.md) and [common-namespace](guest-common-namespace-proof.md) evidence. It independently reads the original640,912-byte ELF `ed618c386528c0b9890c67cbdcb22e1c194f44b034d8e36be2d7f2217fef7dfc`, selected existing main/globals/start instruction records and the immutable Samsung OS index. Fourteen selected regular policy/account/init members, totaling3,869,168 bytes, were copied into ignored firmware with member hashes and tar offsets. The initial thirteen-member metadata snapshot is preserved in ignored history. No OS tree or20GB payload was re-extracted or rehashed; the original archive's whole hash is inherited evidence, separately labeled.

## The discriminating environment edge

The saved original `init_globals_from_data_and_root` contains ANDROID_DATA at0x743c0/getenv0x743c4 and ANDROID_ROOT at0x743d4/getenv0x743d8. It also loads ASEC_MOUNTPOINT at0x74960 and calls getenv at0x7496c. The next instructions are `mov x19,x0` at0x74970 and `strlen` at0x74974: on this selected path the returned pointer reaches strlen without an intervening null guard. This establishes a real nonnull environment input requirement on that path, not a tested crash or an invented `/mnt/asec` default. Only supplying the two commonly named ANDROID variables leaves this actual input unbound.

Original startup already owns layout/user-config/migration writes before publication, as the prior native card establishes. The separate early-boot actions in installd.rc are not a private-clone launch recipe and must not be replayed merely to launch another daemon. The original Samsung root, `/data`, mirror, UUID, user and writable state owners remain the previously identified functional obligations; changing argv/environment cannot replace them.

## Smallest next implementable seam

The current gvi API holds inputs and invokes the real gvo filesystem preparation. Its UID0 check is not exec-profile preparation. The actual gvo child owns the private namespace and resource ledger but exposes no daemon-exec operation or transferable namespace/PID selector. A future launcher therefore belongs **inside that real owned child/control lifetime**, using an owned fork for the native sibling's filesystem-root state. Parent-side `nsenter` using an observed numeric PID is not the existing custody contract.

Root can next define one prepared, default-off native-exec input owner: real reviewed executable/interpreter objects; genuine environment producer; child-local credential/capability/exec-context setup; and the held private view plus explicit native publication/lifetime route. Missing values must remain unavailable rather than caller-supplied `admitted=true` or synthetic readiness. Apply a daemon's pre-exec profile to its own child, preserving ancestor/guest setup and original errors. No API or code implementing that owner is selected here.

Once those inputs exist, the owned child-side exec boundary can be implemented and reviewed without changing the retained canonical host daemon. It still needs actual startup, native-call/deferred-work completion and terminal reap before private-view teardown; filesystem preparation or process creation is not those acknowledgements. This is source-directed implementation work, not a demand to finish every device acceptance case before writing an unselected component.
