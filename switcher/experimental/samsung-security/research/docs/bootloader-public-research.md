# Public bootloader research: SM-S948U1 / S948USQS4BZIG

Checked **2026-11-06 UTC (November 5, 2026 in America/Denver)**. This is a bounded primary-source literature check, not a firmware audit or device test.

**No demonstrated public bootloader-unlock chain matching the supplied SM-S948U1, SM8850, S948USQS4BZIG, One UI 9 / API37 profile was found in the sources searched.** A newly published Samsung bootloader flaw is worth tracking, but exact applicability and unlock capability remain unknown. This is not proof that unlocking is impossible.

The target identifiers and existing kernel-root capability are supplied project premises. Neither current device state nor root persistence was measured here. The bootloader string is retained literally: model, regional firmware and security-patch status must not be inferred solely from its spelling.

## Existing root versus the missing authority

**Inference from the published boundaries:** kernel root acts after the verified boot sequence. It can support runtime integration without demonstrating that an earlier signed boot stage accepts modified images, that rollback restrictions permit an older stage, or that protected bootloader state can be changed. Those are separate claims requiring a matching earlier-stage path. Even a kernel write or permissive SELinux setting does not establish TEE/RPMB or hardware-root-of-trust control. The GBL research itself distinguishes pre-boot state change from hardware attestation.

No property toggle, developer-option label, carrier/SIM unlock, U1 marketing designation, paid-service claim or generic Qualcomm support list was accepted as bootloader-unlock evidence. In particular, Samsung's separate November SIM-lock item is not this authority boundary. This pass found no first-party unlock procedure for the supplied profile; it does not claim Samsung permanently removed every possible code path.
