# Original Samsung installd startup hook

The held AArch64 ELF has room for a direct branch and a bounded acknowledgement stub. The verified fixture preserves ordinary return and register behavior at the original call site. The new code range has no original unwind entry. The fixture contains a zero cookie that suppresses sending and was checked in memory only. [Evidence and exact bytes](../inventory/installd-startup-hook.json)

## Exact success-site placement

The original `main` calls `InstalldNativeService::start()` at `0x8b090` and branches to `0x8b180` on a nonzero result at `0x8b094`. Successful `start()` has already performed publication, pool setup, the original isolation-property read and release-store. The next instruction at `0x8b098` calls `IPCThreadState::self()` via PLT `0x8c380`. The original `0x8b09c` prepares `w1=1` and `0x8b0a0` calls `joinThreadPool`. The native failure edge and instructions after the replaced call remain byte-identical. [Startup and client audit](retained-installd-readiness.md)

| Location | Fixed byte fixture |
| --- | --- |
| ELF program-header table, offset `0x108` | Extend RX PT_LOAD 3's `p_filesz` and `p_memsz` from `0x6e300` to `0x6e398`. Keep its original R/X flags, base `0x20000` and `0x4000` alignment. |
| VA and file offset `0x8b098` | Replace `ba 04 00 94` with `9a 0c 00 14`, a direct `B` to `0x8e300`. |
| VA and file offset `0x8e300–0x8e397` | Replace zero padding with the 120-byte stub, alignment padding, zero cookie and 16-byte acknowledgement. |

The original RX segment stops at `0x8e300`. The gap to the next RW segment at `0x90000` is zero-filled and outside the saved sections. A branch that relies on page rounding alone would target outside the declared segment. The fixture extends the declared segment within its existing final page under both 4 KiB and 16 KiB alignment. No new page or writable-executable segment is needed by these ELF arithmetic checks. There are no selected RELA/Android RELR overlaps or existing encoded direct branch, ADR or literal-load references into the replacement code range. The last checks are bounded static checks over the original image, not general indirect reference proofs.

The trampoline keeps `x18`, callee-saved general registers, SIMD registers and the original saved PAC return record unchanged. It uses a 16-byte aligned temporary stack area and restores SP on every path. A direct `ADR` reconstructs the original call return address `0x8b09c` in `x30`; a direct tail `B` then enters the same original PLT stub at `0x8c380`. The original `self()` supplies `x0` for the unchanged continuation. There are no new indirect branch targets or added imports. The stub may clobber call-volatile registers and flags around the replaced call. The original PAC/BTI note and code are preserved outside the replacement spans.

**Unwind boundary.** The original main FDE covers `0x8aaf8–0x8b213`. The original `.eh_frame_hdr` has 679 entries, ends with function start `0x8bd8c` and indexes no FDE for `0x8e300`. A signal or asynchronous unwind in the stub can encounter this gap even though normal execution restores the frame and return address. A runtime candidate needs an approved unwind treatment and the actual Android loader/profile admission. The original build ID remains historical and cannot identify a successor image.

## One-shot channel contract

1. The private-view supervisor reserves its single launch attempt before forking. It creates a connected private `AF_UNIX SOCK_SEQPACKET` pair, enables `SO_PASSCRED` on its receive end and obtains the real send endpoint's nonzero `SO_COOKIE`. The supervisor holds the receive end, the actual forked child identity/pidfd and sole wait ownership. The child closes the receive end and inherits only the intended send end in reserved FD 198 through exec. There is no app or guest-writable alias for the channel. The supervisor closes its duplicate of the send end and treats ambiguity as closed ingress.
2. The live image would have to carry that exact cookie at `0x8e380` in an immutable image bound to the same fork occurrence. The template supplies no runtime cookie input. Image preparation, exact exec identity, a permitted loader/exec profile and FD reservation belong to the real launch owner. A nonzero per-attempt literal or a different reviewed immutable-input ABI requires a separate selection. A fixed FD alone cannot prevent sending to a reused unrelated descriptor.
3. The stub invokes AArch64 Linux `getsockopt(198, SOL_SOCKET, SO_COOKIE, …)` and checks status, exact eight-byte length and a nonzero matching cookie. Only that branch attempts one connected `sendto` with `MSG_DONTWAIT|MSG_NOSIGNAL`, null destination and no ancillary descriptors. The frame is 16 bytes: `OIDR`, little-endian version 1, little-endian phase 1, and eight zero bytes. It carries no PID, Binder, address or property value. Refusal and send failure preserve the original continuation and never retry. The sender remains an owned daemon descriptor in this fixture. The selected launch must retain it without sharing it or prove its separate cleanup. The cookie check and send are distinct syscalls, so the owner must exclude close/replacement from the check through the send. The selected startup source has not established that interval.
4. The supervisor receives with bounded `recvmsg` under the launch's absolute deadline. Credit requires one exact complete packet, no data or ancillary truncation, and exactly one kernel `SCM_CREDENTIALS` record with the actual owned child PID and admitted UID/GID in the receiver's PID namespace. Reject unexpected ancillary data and retire any received rights under actual ownership. Keep the actual pidfd and unreaped process generation through validation. Numeric PID, EOF and a valid-looking frame are insufficient by themselves. Timeout, wrong credentials, partial or malformed data, exit or ambiguity keep admission closed. Keep the actual child and its view retained for controlled retirement, with no replacement launch on uncertainty.

The raw syscall numbers and socket option values come from the held AArch64 NDK headers. Their availability on the selected device, SELinux and seccomp admission, and correct live FD custody remain external prerequisites. Even a valid frame acknowledges only the successful startup phase. Releasing guest acquisition still requires early caller exclusion and the genuine same-publisher Binder join. [Acquisition contract](retained-installd-readiness.md)

## Offline verification

`python -I -B tools/audit_installd_startup_hook.py` verifies the held input hashes, exact startup instructions, load/relocation bounds, immediate targets and byte-exact inverse. It emits the JSON description of an in-memory fixture. An existing offline Capstone decoder also decoded all 31 branch and stub instructions from the saved replacement bytes. No patched ELF was written, loaded or executed.
