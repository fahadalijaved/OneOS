# Opt-in retained-view writer app source

The separate writer profile composes the reviewed cooperative shell writer with the actual 14-file guarded app overlay. It keeps the existing guarded overlay available as the ordinary stock-writer profile. The stock launcher, root script, update route and package settings are byte-identical in that existing profile.

`tools/prepare_retained_writer_app.py --prepare-writer` writes a complete source overlay to the private `firmware/retained-writer-app` directory. The producer admits the saved resValues profile, its independent review, the reviewed writer patch and shell postimages, and the actual 663,592-byte guarded controller. It refuses an existing destination. The derived Gradle script requires `oneos.retainedWriterGuard=true`, `oneos.debugDownloadMetadata=true`, and the existing `oneos.retainedHandoffFile` option for the pinned v2 controller. The v1 asset option must be absent. The existing Gradle task verifies the supplied v2 asset bytes. A build selecting this source profile would take the changed root script's size and hash from the same asset bytes used to generate the full edition's BuildConfig.

## Writer and preprovision

The external provisioner must supply a real `/dev/oneos-retained-view` directory owned by root:root with mode 0700 and an empty regular `lease` owned by root:root with mode 0600 and exactly one hard link. The protected path and lease must resolve to the same underlying objects for the `su` launcher and the guarded controller throughout the mounted boot lifetime. Provisioning must account for any previous writer or view still active, and the protected directory and lease must stay in place while either owner can use them. The app checks the fixed profile and uses the actual `/system/bin/flock` on its opened descriptor. Missing, invalid or unavailable provisioning refuses before original stage work. This source provides no provisioning or reservation reset entry.

The selected RootScript holds lease FD8 and creates its exact `writer-blocked` reservation before the original bootstrap can write. On the installer path, outer FD3 still pins the stage, FD4 the bin, FD5 the private work directory, and FD6 the script write description. The child receives the lease on FD3, retains its original bin anchor on FD4, and has slots 5–9 available to the original installer. Both ordinary launcher branches also pass the lease as FD3 and wait for the actual root script to return. The inner root script checks the same open description, its exclusive lock and the creator reservation before migration or verb dispatch. The outer creator checks the held lease again before a successful close and may retire only its own exact marker after the child and local cleanup finish. Failure, death and uncertain cleanup can leave the marker in place.

`launch` and `recover` retain the reviewed persistent `legacy-blocked` reservation. In particular, the stock launch starts `oneos_switch.sh` through background `nsenter` and `setsid`. The shell return cannot confirm that writer's end. The selected profile refuses `selfupdate` before bootstrap and before inner dispatch because the original `pm install -r` path could replace the guarded writer with an ordinary app. The stock source profile still has its original update behavior.

## Evidence

The offline producer emitted 14 files. Only RootScript.kt, oneos_root.sh and app/build.gradle.kts differ from the pinned base. All three inverses restore the exact originals, and the eleven other files match byte for byte. Saved-byte readback checked the explicit installer and ordinary descriptor edges, guard-before-dispatch order, opt-in and complete output set. Four offline refusal probes covered a changed child descriptor, a changed child lock mode, a relative path escape and a wrong controller fingerprint.

The overlay was prepared and checked as data. Gradle, the root script, the Android app and the native controller were not run for this step. The stock fake-root shell suite belongs to the ordinary profile. The guarded profile deliberately requires its fixed path and kernel lock, so a later guarded runtime test will need its own approved provisioning environment. Current device preprovisioning, other writers and old launchers, mount-object equivalence, actual lock and close behavior, legacy return reconciliation and protected deployment remain open. The lease coordinates cooperating code and grants no view or authentication authority. The app still exposes no VIEW route. The guarded controller's terminal 3 still leaves kernel release unconfirmed.
