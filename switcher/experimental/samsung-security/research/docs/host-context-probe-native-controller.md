# Native supervisor protocol: offline controller prerequisite

**This is a pure parser/state prerequisite with no selected issuer or live path.** Default behavior is an offline plan; `--run` returns HOLD. The module has no ADB, socket, subprocess, transfer, staging or numeric-signal implementation. Public READY admission, permit construction, write acknowledgement and cancellation all refuse until a real root-observer/transport owner is separately implemented and reviewed. A plain observation dictionary, hash, token or Boolean cannot activate those methods. Native artifact/profile pins remain explicitly pending rather than invented.

The reviewed ff111974 [predecessor controller](host-context-probe-controller.md) and its evidence remain unchanged. The new file lazily loads only that exact pinned source for pure validators. It never calls its main, Adb, operation/staging functions or changes its live flags. The root native supervisor is a separate author's component; this parser does not preapprove its source, build, selected kernel behavior or integration.

## Exact v1 boundary

The received author contract fixes the supervisor path to `/data/local/tmp/oneos-host-context-probe-20261106-fbce6bff/host_probe_supervisor`, with sole argument `--host-context-supervisor-v1`. The root supervisor directly forks one child, which drops its own credentials; the old numeric-su child launcher is not reused. The native profile fixes the nine captured host environment values plus the one JAR CLASSPATH and original app_process/main/argument. No arbitrary environment or command API is added here.

The parser enforces ASCII NDJSON version 1, exact keys, duplicate rejection, an 8,192-byte line limit, 262,144-byte stream budget and 65,536-byte child-output budget. Canonical integers reject JSON booleans/floats. READY requires four actual UID/GID values, groups 1000, signal 9, exact namespace labels and six distinct descriptor roles in fixed order. FD/dev/inode/size/full-mode types and OUTPUT sequence/chunk hex are checked. CLOCK_LOST and UNREAPED_CLOCK_LOST are failure records, never synthetic time or a grace-period claim.

Only the native contract's literal `PERMIT <32-lowercase-hex>\n` and `CANCEL\n` are represented by internal model transitions. Actual construction remains publicly held. The nonce stays transient and is excluded from summary/checkpoint projections. Native PERMIT_ATTEMPTED means possible exec, not completed exec. EXEC_PIPE_CLOSED remains ambiguous, including before READY. Setup failure, signals and terminal REAPED can legally occur without READY; terminal records and Context candidates are kept separate. Missing terminal, incomplete channels, stderr, unknown output or protocol failure remains unresolved even with a hypothetical local exit 0.

OUTPUT bytes are decoded only transiently. The only retained child content is the exact bounded authored Context JSON validated by the frozen source. Unknown stdout/stderr/hex is counted and discarded. A framing/type/cap/decode failure stays latched if its caller catches the exception. Nested JSON decoder failure also taints the session. Partial native frames and partial child output prevent a positive candidate. Locally attempted cancellation cannot later become a positive candidate merely because a terminal record says cancelled:false.

## Predicate, issuer and callback boundaries

The pure observation predicate compares independent root metadata against READY: parent/root identity and ELF hash; child PID/parent/starttime/UID/GID/groups/domain/caps/namespaces; original host environment/build; and each exact `/proc/child/fd/N` object's descriptor number, device, inode, size, mode, hash and descriptor flags. Actual descriptor masks must come from the source-compiled Android ABI, not desktop constants. The observation timestamp must be at least READY's computed emission time and before its deadline. These are consistency predicates, not authentication of their dictionary issuer.

The actual root observer, current process/channel ownership, external FD hash acquisition, selected profile/approval and native transport remain unimplemented. Old shell capability observations are never imported as proof about the new native child. Held-FD matches prove candidate opened objects; native exec still uses a fixed pathname and normal runtime loading. Neither those matches nor READY prove loaded code, post-exec SELinux or parent-death behavior.

Internal `_model_*` methods exist only to exercise the known protocol transitions with deliberately synthetic data. They are not an observer issuer. A single actor thread owns mutations; checkpoint callbacks cannot reenter them. The actor lock is released during external work, then revision/state are checked again before model permit bytes return. Summary projections are detached deep copies, so serializers cannot rewrite later history by annotating snapshots.

The module orders a caller checkpoint callback before model control-byte construction. It does not implement durable controller markers, pipe scheduling, real transport, staging cleanup or a native termination owner. Parsed `nativeReaped` is a protocol record in this component, not independently authenticated actual wait provenance. Summaries explicitly keep rootObserverIssuerImplemented/reapRecordAuthenticated/stageCleanupAuthorized false. A future genuine source/channel owner is needed to attach actual-wait meaning to a REAPED record.

## Bounded verification and remaining work

Source and authored fixture material are sent to the peer before import/execution. Fixtures cover the reported schema/state negatives, callback reentry/uncertainty, cancellation dominance, snapshot isolation, public HOLD, pre-READY failure/reap and output redaction. Positive cases explicitly use synthetic model observations and artificial descriptor-mask bits; they do not manufacture native artifact pins or a root-owned issuer. The one peer-reviewed PC run passed 55 checks with exit 0. External process/socket calls were trapped before import, no live flags or native pins changed, and the bounded foreign-thread callback probe finished/refused as expected. This proves model callback ordering and state isolation, not actual durable storage or a real owner/transport. Exact immutable results are in the paired inventory.

Root still owns native build/ABI/source acceptance, genuine observation/transport API, actual stage/run proposal and separate concrete user approval. No phone/native/Android/Context execution occurs in this task. Even a future genuine host Context result would not admit a cold authority, guest view, security owner, PIN/fingerprint, app keys, CE, recovery or performance outcome.

The native author separately supplied an actual AArch64/API31 preprocessor receipt for descriptor constants. It is recorded as available but unbound evidence; production artifact/profile/mask bindings in this module remain None for this freeze. The fixture masks are deliberately synthetic and are not that ABI evidence. No pending alignment/build/runtime condition is waived.
