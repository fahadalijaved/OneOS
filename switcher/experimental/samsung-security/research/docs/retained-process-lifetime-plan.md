# Retained Samsung process lifetime plan

**The smallest source-supported candidate keeps the original Samsung system_server, its original root zygote parent and the separately owned zygote_next running in place. It requires a distinct guest-only launch/return path.** It must not stop/restart those services, reparent or re-exec the server, change the parent's UID/GID/domain, or suspend required workers. Root has not selected or implemented this topology. No switch, script, native/OEM code or phone control operation ran for this plan.

The plan reuses the frozen [control](retained-authority-control.md), [dependency](retained-authority-dependencies.md), [original-work quiescence](security-authority-quiescence.md), [installed-code profile](installed-oneos-code-profile.md) and [guest data-view](guest-installd-data-view.md) proofs. Locations below refer directly to the packaged OneOS 0.4.57 scripts, whose hashes are recorded in the [inventory](../inventory/retained-process-lifetime-plan.json). This is not a new whole-callgraph or native audit.

Fresh root-acquired read-only observation `6cd6c630…` distinguishes the roles: Samsung SS27202/start32034759 has parent27129; that primary parent is init's child, UID/GID0, domain `zygote:s0`, argv `zygote64`. Separately, init child27126 is UID/GID0, domain `zygote_next:s0`, species `android-native-app`. The primary parent is not zygote_next. Individual before/after identities were stable, but these point samples are not an atomic process tree, all-thread view, source attestation or controlled-survival test. The captured primary init RC independently declares `user root`, the canonical sockets and `--start-system-server`.

Preserve both root processes' real roles and existing credentials; a new UID1000 app_process probe is not their replacement. UID0 identifies these process roles, not permission to authorize guest authentication. Do not adopt or signal the init-owned host processes as if they were direct unreaped children of a new supervisor. Source declarations and sampled PID/parent values do not settle Samsung init's group/cgroup kill, native zygote death/SIGCHLD or automatic restart semantics. The candidate avoids issuing the conflicting stop/restart operations; it does not claim survival after them.

The existing return defaults to reboot at422 and selects its old in-place reconstruction only later. Setting `ONEOS_RETURN_MODE=inplace` is therefore not a retained return; its destructive prelude already ran. Likewise, return722–743 restores crash-recovery properties, zeroes rescue counters and restores persist values. Those source actions cannot acknowledge safe continuation of a host that remained live. Guest boot/crash accounting and global property writers need a real compatible route; the script comments do not prove current Samsung callback behavior.

The guest still needs a real process owner. Switch1418 currently backgrounds `unshare`, remembers `$!`, then samples namespace/root-device. A new owner must hold the actual guest root/zygote and accepted descendants across exec/fork and retirement, distinguish terminal exit from channel EOF and prevent new forks before teardown. Exact direct-child reap ownership or another source-proven custody mechanism is required. The existing root-to-UID1000 diagnostic supervisor is not a ready root-zygote launcher. No group, UID or name-wide kill follows from this plan.

There is no physical credential-writer transfer in this candidate: the same original Samsung graph continues operating. Competing guest credential/biometric/user/native writers must be suppressed or redirected before their constructors/publication; existing guards are not removed merely because capture succeeded. Guest package/user/policy/endpoints and app-start routing must address the same real authority. Required original policy, StrongAuth, AM user-unlock and biometric/session work remains live. Foreground/application ingress and physical display/input ownership need real source gates; blindly disabling host AM/UI/zygote workers can remove required callbacks.

On return, first refuse new guest frontend requests and guest app/fork ingress at their actual producers, including cached handles and direct/local routes. Allow already admitted original work to settle under its existing owners. Enroll the actual AM unlock listener, deferred biometric challenges/resets/removal callbacks, Handler continuations, DPM/policy work and native/storage outcomes identified in the quiescence proof. A router count, queue marker, process death, timeout or void Java return cannot provide those acknowledgements. The coordinator must not block the queues it awaits.

Only after actual guest terminal outcomes and guest-writer/process/view retirement may the same host become foreground. Preserve host security/policy producers throughout; restore only genuinely session-owned presentation/property changes under their current owners, not a stale credential DB, user registry or broad snapshot over legitimate intervening changes. No secret backup or slot/enrollment reset is proposed. Existing global persist/property/SELinux restoration is not automatically a retained-owner reconciliation contract.

If the host parent/server generation dies, source links drift, or a native effect has uncertain completion, stop guest admission and keep every still-live original owner needed to reconcile it. Do not blindly retry a credential mutation, claim drain, construct a replacement writer, or fall through to the old broad-kill return. A separately admitted recovery may eventually reboot/reconstruct; that is a different path and cannot preserve the same process identity or roll hardware state back. No new reboot or recovery action is authorized here.

PC work can now prepare a profile-pinned, default-disabled derivative/action-plan checker for these exact script boundaries; narrow original producer/continuation hook contracts; and a root-guest process-custody prototype with authored fixtures. Such work can prove target selection, forbidden-action rejection and Java/PC bookkeeping. It cannot prove actual original ingress closure, child/native drain or live custody by introducing a `ready`, `paused` or `resumed` Boolean. The current capture/Family helpers only retain/check references.

Before any launch prefix can be selected, the concrete open edges are actual init/zygote/watchdog lifetime ownership; guest-only socket/data/property/Binder routing; coherent guest identity plus physical presentation/biometric ownership; and original callback/native/persistence completion and return reconciliation. The captured init RC's stopped-zygote action disables softdog and its restart list affects FUSE/media/network; the native implementation and current watchdog owner are not closed by those declarations. Retaining the original process avoids cold constructor work, but does not close these coexistence controls. The finite next implementation should target those control producers, not add another passive capture or a fake pause/resume facade.
